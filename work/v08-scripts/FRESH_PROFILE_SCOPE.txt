Fresh in-memory preference session

scene_profile_v08_options has trailing int fresh_profile:0 means unknown,
1 explicitly creates a new initially empty host preference session. Other flags
reject before provider installation. The flag is immutable per realm; its
mutable dictionary is Lua-owned and shared by the getter and setter closures.
The closures retain no caller pointer, native profile, or filesystem resource.

PROFILE.get_variable admits exactly one Lua numeric signed-int32 hash and returns
exactly one stored number or nil if missing. PROFILE.set_variable admits exactly
two arguments: that hash and a numeric signed-int32 value. It replaces a matching
entry or creates a new entry and returns zero values. Numeric strings, nil values,
booleans, tables, fractions, NaN/infinity, out-of-range numbers and wrong arities
fail before mutation. Both calls error when the preference session is unknown.
Only this numeric subset is modeled; no deletion, table-valued variables,
persistence, save loading, native profile import, or profile file access exists.
Dictionary allocation uses the realm's Lua allocator and memory limit.

initial_entries=0,imported_user_profile=0,persistence=0. This describes a new
Android session, not the user's existing game profile. Existing user profiles
and saves remain untouched. The expanded macro descriptor array is unchanged.
