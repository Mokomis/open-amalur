Worker lifetime

The render worker gets its own JNIEnv from Activity.vm, attaching only when
needed. It never uses Activity.env from the callback thread. Device enumeration
uses local JNI frames and clears query-owned exceptions. Only a worker that
attached itself detaches itself. Lua providers retain no JNI references.

Initial inventory is queried before bootstrap. While rendering/resumed it is
refreshed at most every500ms, or promptly after a resume/configuration epoch
change. Paused/no-window loops keep their existing blocking behavior, so no
claim of background hotplug monitoring is made. Sorted IDs avoid reorder-only
log churn. Logs distinguish unknown versus known counts and show source masks
and virtual status only on change. Source counts describe Android logical input
devices, not necessarily the number of distinct physical controllers.

The selected Android logical STANDARD policy is separately logged and copied
through the v08 profile. Android keycode A confirms and B backs; this is explicit
new host behavior, not a native kind or a connection inference. Inventory does
not alter the policy. Native kind15 being identified as SwitchProController does
not imply every Android controller with reversed labels should become native15.

Only TOUCHSCREEN source motion reaches touch orbit/pinch. Joystick, mouse and
key events remain unhandled here until an actual action consumes them; the
observer return value is not used as an event-consumed flag. This update does
not implement controller camera movement, per-frame gameplay, or input dispatch
to recovered Lua. Touch gesture bookkeeping resets at queue replacement/pause.

After a validated scene loads, bootstrap requests the same SpaceCommon root and
on_object_creation_complete event under128MiB/10M-instruction bounds. A failed
bootstrap remains diagnostic and returns no realm. A fully successful realm is
retained in a worker-local variable, stays idle, and is destroyed by the same
worker during shutdown before JNI detach and mesh cleanup. Activity destruction
still wakes/joins the worker before releasing Activity-owned resources.
The shader, mesh loading, projection, geometry and draw behavior are unchanged.
