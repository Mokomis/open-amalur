# Branch and capture reconstruction

This continuation adds an explicitly enabled native-static profile for branch instructions and captured variables. It produces Lua 5.1 source using a **program-counter dispatcher**, not recovered high-level `if`/loop source structure. Each instruction retains its original word, file offset, native evidence references, register accesses, and control-flow edges in the IR.

Conditional TEST, TESTSET, and comparisons own the following JMP word. The jump target is calculated relative to that word; the alternative successor skips the pair. Edges into consumed cache/capture/paired-JMP words are rejected. LOADBOOL skips exactly its low-eight-bit C word count. Reachability and a predecessor-intersection dataflow pass distinguish guaranteed register definitions from writes that occur on only one branch. TESTSET's write is attached only to its taken edge. Hidden-cache shortcuts require both a known immediate producer and a control-flow predecessor check.

CALL_I_R1 uses the hidden cached callable type while taking the actual callee from its register. Its fixed-argument/result form is admitted only after a confirmed matching producer, with no incoming branch that bypasses that producer. No call is assumed to refresh the cache with its return value. Generated fixed calls require a Lua/C function value and reject unmodeled callable-object behavior explicitly.

Cached field reads also admit explicitly confirmed MOVE, GETUPVAL, and prior field-result producers, retaining the same register and sole-predecessor checks. This permits reading a field from a captured table without assuming the hidden cache is always equivalent to encoded B.

Each generated invocation owns a fresh table of mutable register cells. A CLOSURE descriptor with low byte 1 captures the current register cell; low byte 0 forwards an existing parent upvalue cell. The 17-bit descriptor index is extracted from bits 8–24. Descriptor high opcode bits are not interpreted as instructions. Sibling closures share the same cell. Forwarded captures retain the same cell, rather than copying its current value. Capturing a closure's own destination preserves recursive self-reference.

GETUPVAL/SETUPVAL read and write the cell's `value` property. CLOSE detaches current-frame cells at or above its register threshold: existing closures retain the old cells, while later writes/captures use replacements. Returning naturally preserves cells referenced by surviving closures; separate function invocations never share their register-cell table. Closure factories are created inline in the current environment, preserving Lua 5.1 `module()` environment changes.

A standalone captured-child draft is exported as a **capture factory**: `function(__uv)` returns the reconstructed function. Its argument is a zero-indexed table of shared `{value = ...}` cells. This is a review/binding contract, not a recovered original function signature. Whole-script nested closures supply the cells automatically. A root script with unbound captures remains unresolved.

Comparisons include explicit runtime guards. Equality admits nil, booleans, strings, and signed 32-bit integer numbers; ordered comparisons admit matching string or signed-integer operands. Tables, userdata, custom Havok values, floating-point numbers, and other unmodeled domains raise a clear error rather than silently assuming standard Lua metamethod behavior. Supported-body counts therefore describe this admitted domain, not universal Havok equivalence.

The bounded table subset includes zero-hint NEWTABLE, SETFIELD/SETFIELD_R1, GETTABLE_S, and producer-proven SETUPVAL_R1. Writes and indexed reads require ordinary Lua tables with no metatable and string or signed-integer keys. NEWTABLE capacity arguments other than B=C=0 remain unresolved. GETTABLE_S consumes two DATA words but does not establish hidden-cache knowledge. Native Havok structures, userdata, metamethod-backed tables, SETLIST, and open list forms remain outside this subset.

Open calls/returns, integer arithmetic, unsupported cached forms, additional opcodes, and unconfirmed capture forms remain unresolved. Unknown instructions on reachable paths prevent body emission. Proven unreachable instructions remain recorded but do not block a fully known reachable path. After an unsupported transfer with unknown successors, later reachability is explicitly `unknown` (`reachable: null`), not falsely classified as unreachable. Unsupported bodies retain explicit error stubs.

The extended profile is required; legacy profiles keep the earlier conservative straight-line behavior. Tests run on Windows. Unit tests, synthetic Lua 5.1 runtime fixtures, syntax checks, and real-sample coverage are distinct evidence and should be reported separately. Generated Lua behavior is not a demonstration of execution in the native Havok VM.
